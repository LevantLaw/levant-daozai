# 岛仔 PRD：通知展示与生命周期治理

- 编号：PRD-003
- 状态：已实现，待手工验收
- 日期：2026-11-21
- 适用版本：岛仔 v0.6.66 之后（基于 `local` 分支 2026-11-21 工作区）
- 变更类型：通知展示模型收敛 + 入口职责调整 + 设置信息架构调整
- 硬约束：
  - 不改现有 `settings.txt` 键名与默认值。
  - 不改各来源的触发条件（健康间隔、待办到期、邮件同步、IM 监听等）。
  - 不把岛体组件开关搬出「岛体 → 岛上显示」。
  - 先锁定来源策略表，再分阶段实现；未确认项不得直接开工。
  - 不要求一次性合并模块；先统一模型与行为，再决定是否合并代码。

---

## 0. 调研结论

- 现状是四套实现：横幅、页面徽标、事件容器、铃铛 / 未读图标 / 状态灯。
- 概念上可以收敛为：**两套展示面（横幅、岛体图标）+ 两个专用入口（铃铛、AI 状态灯）**。
- 页面徽标和事件容器里的徽标是同一套图标：共用 `paint_badge`、`badge_label`、`badge_width` 和点击目标；设置页已经按「常驻显示 / 事件显示」分组。事件容器额外承载天气、额度、专注、音乐、电量等非徽标组件。
- 铃铛现状不是 Windows 专用：邮件、即时通讯、外部通知都会点亮；点击时 `windows_unread` 为真进 Windows 通知页，否则进邮箱页。
- AI 状态灯在展开态已经可点并进入 AI 页（`agent-pill`），不是完全不可点；缺口是收起态不能直接点，以及可发现性。
- AI 状态灯和 AI 提示音都由 agent tick 驱动，但提示音不受提醒总开关控制。
- 即时通讯使用独立的未读来源图标，不共用铃铛；QQ 属于即时通讯。

## 1. 背景与问题

用户看到的行为可以概括为：

> 消息先上横幅；有些横幅带按钮，有些跳功能页；有些横幅收起后岛上留一个图标，有些直接消失。

但代码里没有一条统一规则，导致：

- 同一个「提醒」在不同来源下表现不同，用户无法形成稳定预期。
- 铃铛既像 Windows 通知入口，又像邮件入口，还会被即时通讯点亮。
- AI 状态灯看得到，但收起态点不了，用户不知道它是入口。
- 页面徽标和事件容器做同一件事，却是两套模块、两套时序。
- 有些图标看得到但点不了，或者点开后不是用户以为的页面。
- 横幅和图标的时间窗口互相覆盖，出现「横幅刚收起，图标也过期」。
- AI 等待这类高优先级事件反而没有横幅，只有一个小状态灯。
- 设置页里「通知」「提醒」「展开与收起」「岛体组件」的边界不清晰。

本 PRD 的目标不是重写通知系统，而是先把模型收敛，再按阶段修正偏差。

---

## 2. 目标与非目标

### 2.1 目标

1. 把四套实现收敛为两套展示面 + 两个专用入口。
2. 铃铛只承担「非即时通讯的 Windows 通知」入口。
3. AI 状态灯承担 AI 会话入口，收起态和展开态都可点。
4. 页面徽标和事件容器徽标统一为「岛体图标」，分常驻 / 事件两类。
5. 修正横幅与图标的时序冲突，保证图标在横幅结束后仍然可见。
6. 明确悬停行为：横幅收起后悬停只展开正常面板，不召回横幅。
7. 明确 `提醒方式` 的适用范围。
8. 在「行为」页提供「岛体组件 / 横幅 / 展开」三态入口，但不搬组件开关。

### 2.2 非目标

- 不重写通知队列、徽标和事件容器的全部代码。
- 不改各来源的触发条件与业务逻辑。
- 不改 `settings.txt` 键名、默认值和保存时机。
- 不新增通知历史页；作为后续可选需求。
- 不把岛体组件开关搬出「岛体 → 岛上显示」。
- 不合并「横幅」和「展开与收起」两个分组。
- 不改变即时通讯的窗口跳转方式（仍然跳对应软件，不新增功能页）。
- 不改变 AI Hook 的安装、审批和会话保留逻辑。

## 3. 术语与目标模型

### 3.1 术语

| 术语 | 含义 |
|---|---|
| 事件 | 健康、待办、邮件、会议、专注、饮水达标、低电量、系统 HUD、即时通讯、Windows 通知、AI 会话 |
| 数据变化 | 天气、额度、电量、音乐、专注进度等，不是消息，默认不弹横幅 |
| 横幅 | `notice`，岛体展开成横向条，显示标题 / 正文 / 按钮 |
| 展开页 | `show_page`，完整面板打开到具体功能页，停留 `page_hold_secs` |
| 岛体图标 | 岛上的一枚图标，分常驻和事件两类 |
| 常驻图标 | 条件驱动，条件解除前一直显示；即页面徽标 |
| 事件图标 | 数据变化或事件触发后定时显示；即事件容器成员 |
| 专用入口 | 铃铛、AI 状态灯；点击进入固定页面 |
| 外部跳转 | 不打开岛内功能页，直接切到对应软件窗口 |

### 3.2 目标模型

```text
展示面
  横幅（瞬时）
  岛体图标
    常驻图标（条件驱动，直到处理）
    事件图标（定时 10s，或数据变化）
专用入口
  铃铛 → Windows 通知页（非即时通讯的 Windows 通知）
  AI 状态灯 → AI 会话页（AI 会话状态 + hook 提示音）
```

- 页面徽标 = 常驻图标；事件容器里的徽标 = 事件图标；两者共用同一套绘制和点击。
- 铃铛和状态灯不是通知机制，是入口；横幅和岛体图标才是展示面。
- 铃铛是未读入口，AI 状态灯是状态入口；前者按 Windows 未读出现 / 消失，后者在 AI 模块开启时常驻。
- 即时通讯未读来源图标归入岛体图标的未读类，不共用铃铛。
- 事件容器中的天气 / 额度 / 专注 / 音乐 / 电量是数据组件，不是徽标；归入事件图标。

### 3.2.1 通知分支流程图

```text
来源
├─ 数据变化（天气 / 额度 / 电量 / 音乐 / 专注进度）
│   └─ 不弹横幅 → 事件图标（10s，从变化开始）→ 点击进功能页
│
└─ 消息 / 提醒
    ├─ AI 等待（提问 / 审批） → 直接展开详情子页 → 处理完收起（展开提醒）
    ├─ AI 完成 / 失败 / 中断 → 直接打开 AI 会话页（列表） → 状态灯
    └─ 其余 → 先出横幅
        ├─ 信息（系统 HUD） → 自动收起 → 无图标
        ├─ 动作（健康 / 专注 / 低电量） → 按钮处理
        ├─ 跳转（待办 / 邮件 / 会议 / 饮水达标 / Windows） → 查看 → 功能页
        └─ 外部跳转（即时通讯） → 查看 → 对应软件
             │
             ▼
        横幅结束：条件是否未解除？
        ├─ 是 → 常驻入口（岛体图标，含 IM 未读；或铃铛）→ 点击进对应页面或软件
        ├─ 信息性（如有） → 事件图标（10s，从横幅结束开始）→ 点击进功能页
        └─ 否 → 无图标

入口分类
├─ 岛体图标
│   ├─ 常驻（含 IM 未读）
│   └─ 事件（临时）
├─ 铃铛：Windows 未读（非 IM）
└─ AI 状态灯：AI 会话状态（常驻，非未读驱动）

AI 事件
├─ 等待 / 审批 / 问答：见 5.8，直接展开详情
├─ 完成 / 失败 / 中断 → 直接打开 AI 会话页（列表） → AI 状态灯
└─ 可能已中断 → 不展开 → AI 状态灯黄色 → 提醒一次后隐藏

悬停
└─ 横幅收起后悬停岛体 → 展开正常面板，不召回横幅
```

**「条件未解除」的定义**：该来源仍有需要用户处理的状态。

| 来源 | 条件未解除 |
|---|---|
| 邮件 | 有未读邮件 |
| 健康 | 提醒未确认 |
| 待办 | 到期未完成 |
| 会议 | 会议尚未开始 |
| 即时通讯 | 未读未处理 |
| Windows 通知 | 未打开通知页 |

一次性事件（系统 HUD、专注、饮水达标、低电量）在横幅结束或用户处理后即视为条件解除，不留常驻入口。每个来源的最终落点以第 6 节来源策略表为准。

AI 状态灯是常驻状态入口，不按未读驱动；等待 / 审批只改变颜色和提示音，不改变「是否显示」。

> 流程图只描述判定顺序，不表示「横幅类型决定落点」。落点由来源和「条件是否未解除」决定；横幅类型只决定按钮形态。

### 3.3 关键约束

- **横幅不持久化**：横幅始终定时收起；需要持续提示时使用常驻图标，不使用常驻横幅。
- **悬停不召回横幅**：横幅收起后，悬停岛体只展开正常面板。
- **图标必须可点**：每个常驻图标和事件图标都要有明确点击目标。
- **图标计时不与横幅重叠**：有横幅时，事件图标从横幅结束后开始计时；没有横幅时，从数据变化开始。
- **铃铛只由 Windows 通知点亮**：邮件和即时通讯不使用铃铛。
- **状态灯点击进 AI 页**：收起态和展开态都成立；AI 提示音与状态灯同源。

## 4. 现状（as-is）

### 4.1 四套实现与概念归属

| 现状实现 | 概念归属 | 说明 |
|---|---|---|
| 横幅 `notice` | 展示面 · 横幅 | 瞬时；所有来源共用 |
| 页面徽标 `page_badges` | 展示面 · 岛体图标（常驻） | 条件驱动；邮箱 / 健康 / 待办 / 置物架 / 日程 / 勿扰 |
| 事件容器 `event_tray` | 展示面 · 岛体图标（事件） | 10 秒；徽标事件 + 天气 / 额度 / 专注 / 音乐 / 电量 |
| 铃铛 | 专用入口 | 现状被邮件 / 即时通讯 / Windows 通知共用 |
| 未读来源图标 | 专用入口 / 岛体图标（未读） | 即时通讯专用，不共用铃铛 |
| AI 状态灯 | 专用入口 | 展开态可点进 AI 页；收起态不可直接点 |

### 4.2 来源矩阵

| 来源 | 横幅 | 横幅按钮 | 横幅后 | 入口 | 系统通知 / 声音 |
|---|---|---|---|---|---|
| 系统 HUD（音量 / 大写 / 输入语言 / 网络 / 电源 / 蓝牙） | 2.5s | 无（音量可交互） | 无 | — | 无 |
| 健康（喝水 / 久坐） | 8s | 知道了 / 喝一口·起身了 | 健康徽标到确认 | 健康页 | 有 |
| 待办到期 | 8s | 查看 → 待办页 | 待办徽标到完成 | 待办页 | 有 |
| 新邮件 | 8s | 查看 → 邮箱页 | 邮箱徽标到已读 + 铃铛 6s | 邮箱页 / 铃铛 | 无 |
| 会议提醒 | 12s | 关闭 / 查看 → 日程页 | 日程徽标 10s | 日程页 | 有 |
| 专注计时 | 8s | 开始 | 无 | — | 有 |
| 饮水达标 | 8s | 查看 → 健康页 | 无 | 健康页 | 有 |
| 低电量 | 8s | 知道了 | 无 | — | 有 |
| 即时通讯 | `notice_hold_secs` | 查看 → 软件 / 关闭 | 未读来源图标 + 铃铛 `hold` | 对应软件 / 铃铛 | 无 |
| Windows 通知 | `notice_hold_secs` | 关闭 | 铃铛红点到打开通知页 | Windows 通知页 | 无 |
| AI 等待 / 问答 | 无 | — | 详情页（开关开）或状态灯（关） | AI 页（展开态可点） | 无 |
| AI 完成 / 失败 / 中断 | 无 | — | 直接打开 AI 会话页（列表） | AI 页（展开态可点） | 无 |
| AI 可能已中断 | 无 | — | 状态灯；提醒一次后隐藏 | AI 页（展开态可点） | 无 |

铃铛现状补充：

- 邮件、即时通讯、外部 Windows 通知都会设置 `notification_bell_until`。
- 只有非即时通讯的 Windows 通知会设置 `windows_unread`。
- 点击铃铛时，`windows_unread` 为真进 Windows 通知页，否则进邮箱页。
- 因此铃铛目前是「有新通知」的通用指示，不是 Windows 专用入口。

### 4.3 现存不一致

1. **铃铛职责混用**：邮件、即时通讯、Windows 通知共用；点击还有邮箱页兜底。
2. **AI 状态灯收起态不可直接点**：展开态已可点，收起态只能先展开岛体。
3. **页面徽标与事件容器双实现**：徽标子集同源，但模块、时序、设置分散；事件容器在横幅期间不可见。
4. **事件容器非徽标组件不可点**：天气 / 额度 / 专注 / 音乐 / 电量只能看，不能进功能页。
5. **时序冲突**：
   - 会议徽标 10 秒 < 横幅 12 秒。
   - 邮件铃铛 6 秒 < 横幅 8 秒。
   - 即时通讯铃铛窗口等于横幅时长，横幅结束后铃铛也到期。
6. **AI 等待跳过横幅**：高优先级事件直接进详情页，不再先出横幅。
7. **AI 完成直接打开 AI 会话页**：完成、失败、中断不弹横幅，可能中断只更新状态灯。
8. **`提醒方式` 范围不清**：只覆盖 `system=true` 的内部提醒；IM、Windows 通知、AI、HUD 不跟随。
9. **AI 提示音不受总开关控制**：`agent_tick` 在判断 `settings.notifications` 之前就播放提示音。
10. **行为页三态入口缺失**：有「横幅」和「展开」，但没有「岛体组件」入口。

### 4.4 事实确认与修改可行性

#### A. 铃铛 = 除 QQ 外的 Windows 通知入口

- **现状**：不成立。铃铛被邮件、即时通讯、外部通知共同点亮；点击有邮箱页兜底。
- **判断**：这是目标模型，不是现状。收窄可行。
- **修改点**：
  - `receive_notification_from` 里把 `notification_bell_at/until` 移入 `known.is_none()` 分支，只让非即时通讯的 Windows 通知点亮铃铛。
  - `receive_messenger_reminder`、`reveal_messenger_notice` 不再点亮铃铛。
  - 新邮件提醒不再点亮铃铛。
  - 铃铛点击只进 Windows 通知页，删除邮箱页兜底。
- **风险**：`notification_bell_until` 还用于岛上歌词紧凑模式的提示和布局。收窄后，邮件 / 即时通讯在该模式没有铃铛提示，需要单独决定是否保留一个紧凑提示位。

#### B. AI 状态灯点击进入 AI 会话页

- **现状**：部分成立。展开态已经有命中区 `agent-pill`，点击 `show_page(AI_PAGE)`；收起态没有直接命中区，点击岛体是展开。
- **判断**：入口逻辑已经存在，缺口是收起态直接点击和可发现性。可行。
- **修改点**：
  - 在收起态给状态灯加命中区，优先于岛体展开；或在 PRD 里明确「先展开，再点状态灯」。
  - 保持展开态现有行为。
- **风险**：与岛体整体点击 / 拖拽的命中优先级冲突，需要实测定序。
- **声音**：状态灯和 AI 提示音都由 `agent_tick` 的同一批 hook 事件驱动；提示音目前不受 `settings.notifications` 控制。状态灯不是声音的开关，但两者同源。

#### C. 事件容器和页面徽标是同一件事

- **现状**：徽标子集成立。两者共用 `paint_badge`、`badge_label`、`badge_width` 和点击目标；`page_badges()` 通过 `badge_in_tray()` 排除事件容器成员；设置页已按「常驻显示 / 事件显示」分组。
- **判断**：用户判断成立。事件容器额外承载天气 / 额度 / 专注 / 音乐 / 电量等非徽标组件，这部分不属于页面徽标。
- **修改点**：
  - 术语统一为「岛体图标（常驻 / 事件）」。
  - 时序统一：事件图标在横幅结束后开始计时；可处理事件持续到条件解除。
  - 代码模块可暂不合并；先统一行为和设置语义，再决定是否合并 `page_badges` 与 `event_tray`。
- **风险**：事件容器的非徽标组件没有统一点击语义，需要单独定义。

## 5. 目标规则（to-be）

### 5.1 总原则

1. 展示面只有两套：横幅、岛体图标。
2. 岛体图标只有两类：常驻、事件。
3. 专用入口只有两个：铃铛、AI 状态灯。
4. 消息 / 提醒事件先上横幅；数据变化不弹横幅。
5. 横幅结束后，按来源留下常驻图标、事件图标或无图标。
6. 悬停岛体只展开正常面板，不召回横幅。
7. 每个常驻图标和事件图标必须可点。
8. 图标可见时间不能被横幅吃掉。

### 5.2 横幅类型

| 类型 | 交互 | 适用来源 |
|---|---|---|
| 动作横幅 | 按钮直接处理事件，不跳页 | 健康、专注、低电量 |
| 跳转横幅 | 一个「查看」按钮进功能页 | 待办、邮箱、AI、饮水达标、会议、Windows 通知 |
| 信息横幅 | 无按钮，自动收起 | 系统 HUD |
| 外部跳转横幅 | 「查看」切到对应软件 | 即时通讯 |

规则：

- 除信息横幅外，每个横幅至少有一个明确动作。
- Windows 通知横幅建议新增「查看」→ Windows 通知页，而不是只有「关闭」。
- 动作横幅的按钮语义固定：确认 / 记录 / 开始，不使用含糊的「查看」。

### 5.3 生命周期

| 结束方式 | 适用 | 规则 |
|---|---|---|
| 常驻图标 | 需要用户处理的事件 | 横幅结束后图标保留，直到处理 |
| 事件图标 | 信息性数据变化 | 固定 10 秒；有横幅时从横幅结束后开始计时 |
| 无图标 | 一次性信息 | 横幅结束即消失 |

- **不引入持久横幅**：横幅始终定时收起。需要持续提示时使用常驻图标或页面。
- **岛体展开时暂停横幅计时**：保持现有行为；展开期间到达的非 HUD 横幅排队，收起后显示。
- **AI 等待的常驻详情页**：作为明确例外单独定义（见 5.8），不计入「持久横幅」。

### 5.4 岛体图标（常驻 / 事件）

| 类别 | 触发 | 生命周期 | 点击 |
|---|---|---|---|
| 常驻图标 | 条件成立（未读、待确认、到期、勿扰） | 条件解除前一直显示 | 功能页；勿扰切换 |
| 事件图标 | 数据变化或事件触发 | 10 秒；有横幅时从横幅结束后计时 | 功能页 |

规则：

1. 常驻图标就是页面徽标；事件图标就是事件容器里的徽标。两者共用同一套绘制、标签和点击。
2. 设置页「岛体 → 岛上显示」的「常驻显示 / 事件显示」就是这两类，不新增第三类。
3. 事件容器中的天气 / 额度 / 专注 / 音乐 / 电量是数据组件，归入事件图标；必须可点进对应功能页，或明确标为只读。
4. 可处理事件（邮件、健康、待办、日程）放进事件显示时，图标持续到条件解除，不使用 10 秒默认值；否则禁止把它们放进事件容器。
5. 同一来源只保留一个主入口：常驻图标或事件图标，不重复。
6. 事件图标在横幅期间可以隐藏，但横幅结束后必须可见，计时不因横幅而缩短。

### 5.5 专用入口

#### 5.5.1 铃铛

- 只由「非即时通讯的 Windows 通知」点亮；QQ 及其他即时通讯不点亮铃铛。
- 点击铃铛始终进入 Windows 通知页，不再回退到邮箱页。
- 没有 Windows 未读时铃铛隐藏。
- 邮件使用邮箱图标作为入口，不使用铃铛。
- 即时通讯使用未读来源图标作为入口，不使用铃铛。
- 岛上歌词紧凑模式下，铃铛不再是通用通知指示；邮件 / 即时通讯是否需要单独的紧凑提示位，见待确认项。

#### 5.5.2 AI 状态灯

- 在「岛体 → 岛上显示」中由「AI 会话状态灯」开关控制显示。
- 颜色：蓝色运行、橙色呼吸等待、黄色可能中断；无活跃会话时暗色占位。
- 点击状态灯进入 AI 会话页；收起态和展开态都成立。
- 状态灯和 AI 提示音由同一批 agent hook 事件驱动；提示音是否受提醒总开关 / 声音设置控制，见待确认项。
- 状态灯隐藏时，AI 提示音是否继续播放，见待确认项；不能出现「入口没了但声音还在」的默认行为。

### 5.6 悬停

- 横幅收起后，悬停岛体展开正常面板（当前页或上次页）。
- 不重新显示横幅；横幅没有「再看一次」入口。
- 需要回看时，后续可增加通知历史页；本 PRD 不做。
- 悬停铃铛 / 状态灯 / 未读来源图标时显示 tooltip；点击才跳转。

### 5.7 即时通讯

- 即时通讯没有岛内功能页，横幅「查看」和常驻未读来源图标都跳对应软件。
- 一个未读：点击未读来源图标直接跳转。
- 多个未读：点击图标展开面板，在未读胶囊里选择账号。
- 铃铛不用于即时通讯；QQ 及其他即时通讯都使用未读来源图标。
- 即时通讯的常驻入口是未读来源图标，不是铃铛。

### 5.8 AI 会话

等待用户选择 / 问答（展开提醒）：

- 直接展开 AI 详情页（选择页 / 审批页），不先出横幅，也不在收起后回到横幅。
- 待处理期间保持展开；用户在岛上输入 / 编辑时排队，结束后再展开。
- 「用户选择」「审批」分别控制是否展开；关闭后只保留状态灯和列表里的「处理」。

完成 / 失败 / 中断（展开提醒）：

- 直接打开 AI 会话页（会话列表），不先出横幅。
- 用户在岛上输入 / 编辑、其他横幅显示中或已有待处理详情时排队，结束后再打开。
- 「完成」「中断」「失败」分别控制是否展开；关闭后只保留状态灯和列表。

可能已中断（只更新状态灯）：

- 运行中超过 10 分钟没有事件时状态灯转黄，不展开、不弹横幅。
- 提醒一次后会话从列表隐藏。
- 状态灯必须可点，点击进入 AI 页。

AI 提示音：

- 建议受 `settings.notifications` 和 `settings.sound` 控制，与「提醒方式」一致；
- 或明确写成独立通道，并在设置页说明。二选一（见待确认项）。

### 5.9 提醒方式

- `提醒方式` 只控制岛仔自己发出的 Windows 系统通知和声音。
- 覆盖范围：`system=true` 的内部提醒——健康、专注、待办、会议、低电量、饮水达标。
- 不覆盖：即时通讯、Windows 通知读取、AI 会话、系统 HUD。
- 文案二选一：
  - A. 保留「提醒方式」，增加一行说明：「只影响岛仔自己的系统提醒；IM / Windows / AI 不受影响」。
  - B. 改名为「系统提醒」，从名称上限定范围。

- 页标题下不加说明文字；`提醒方式` 的适用范围说明放在控件旁。

### 7.3 岛体页

- 「岛体 → 岛上显示」已经按「常驻显示 / 事件显示」分组，本 PRD 沿用这两个名称，不再造新词。

- 铃铛不是岛体组件，不放进「岛上显示」；它属于 Windows 通知页。

### 7.4 不做

- 不新增只有跳转按钮的多个分组；三态入口用「岛体组件」一个链接即可。
- 不把「提醒」页改名；本 PRD 只调整「行为」页。
- 不在行为页重复岛体组件开关。

## 9. 验收标准

1. 文档和实现都按「两套展示面 + 两个专用入口」描述，不再把四套机制并列。
2. 铃铛只由非即时通讯的 Windows 通知点亮；点击始终进 Windows 通知页；邮件、即时通讯、AI 不点亮铃铛。
3. AI 状态灯在收起态和展开态都可点，点击进 AI 页；状态灯隐藏时不会出现「入口没了但声音还在」的默认行为。
4. 页面徽标和事件容器徽标共用同一套绘制、标签和点击；设置页仍按「常驻显示 / 事件显示」分组。
5. 事件容器里的天气 / 额度 / 电量 / 音乐 / 专注进度图标可点，或明确标为只读。
6. AI 等待直接展开详情；完成、失败、中断直接打开 AI 会话页；可能中断只更新状态灯；各事件分别受对应开关控制。
7. 每个横幅有明确类型：动作 / 跳转 / 信息 / 外部跳转；除信息横幅外至少有一个动作。
8. 横幅结束后：需要处理的事件有常驻图标，直到处理；信息性数据变化有事件图标或常驻组件更新；一次性信息无图标。
9. 悬停横幅已收起的岛体，展开正常面板，不重新显示横幅。
10. 图标可见时间不被横幅吃掉：会议、邮件、即时通讯、事件图标在横幅结束后仍然可见。
11. 即时通讯：一个未读点击直接跳软件；多个未读展开胶囊选择账号；铃铛不用于即时通讯。
12. `提醒方式` 的作用范围有明确文案；AI 提示音门控与决策一致。
13. 行为页有「岛体组件 / 横幅 / 展开」三态入口；岛体组件只链接，不放开关键；横幅停留仍在横幅组。
14. 不改 `settings.txt` 键名和默认值；现有设置保存时机不变。
15. 现有通知、健康、邮件、日程、IM、AI 相关测试全部通过，并新增来源策略表覆盖。

## 附录 A：现状与目标差异清单

| 项目 | 现状 | 目标 |
|---|---|---|
| 总体模型 | 四套实现并列 | 两套展示面 + 两个专用入口 |
| 铃铛 | 邮件 / IM / Windows 共用；点击可能进邮箱页 | 只由非 IM 的 Windows 通知点亮；点击只进 Windows 页 |
| AI 状态灯 | 展开态可点；收起态不可直接点 | 收起态和展开态都可点进 AI 页 |
| 页面徽标 / 事件容器 | 徽标子集同源，但两套模块、两套时序 | 统一为「岛体图标（常驻 / 事件）」；共用绘制和点击 |
| 事件容器非徽标组件 | 天气 / 额度 / 专注 / 音乐 / 电量不可点 | 全部可点进对应功能页 |
| AI 等待 | 无横幅；详情页或状态灯 | 直接展开详情；开关关闭时只留状态灯 |
| AI 完成 | 直接打开 AI 会话页 | 保持直接打开；可能中断只更新状态灯 |
| 横幅类型 | 各来源特判，无统一分类 | 动作 / 跳转 / 信息 / 外部跳转四类 |
| 持久化 | 图标 / 页面 / 铃铛 / 状态灯四套 | 常驻图标 / 事件图标 / 无图标三档 |
| 横幅持久化 | 无 | 仍无；持久化交给图标 |
| 悬停 | 展开正常面板，不召回横幅 | 保持；写入规则 |
| 会议图标 | 10 秒，常被 12 秒横幅盖掉 | 保留到会议开始 |
| 邮件铃铛 | 6 秒，常被 8 秒横幅盖掉 | 邮件改用邮箱图标；铃铛专用于 Windows 通知 |
| IM 铃铛 | 窗口等于横幅时长，收起后到期 | 未读来源图标到处理；铃铛不用于 IM |
| 事件容器 | 横幅期间不可见，10 秒窗口被吃掉 | 计时从横幅结束后开始，或持续到条件解除 |
| `提醒方式` | 只覆盖 `system=true` 内部提醒，名称易误解 | 改名「系统提醒」或增加范围说明 |
| AI 提示音 | 不受总开关 / 声音控制 | 受总开关控制，或明确写成独立 |
| 行为页入口 | 展开与收起、通知、避让 | 岛体组件（链接）、横幅提醒、展开与收起、避让 |
